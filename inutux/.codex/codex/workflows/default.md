# Workflow General de Desarrollo

## Objetivo

Definir el flujo estándar que deben seguir todos los agentes antes de realizar cambios en cualquier proyecto.

---

## Paso 1 — Comprender

Responsable:
- Project Manager

Acciones:
- Comprender la solicitud.
- Definir el objetivo.
- Identificar el alcance.

---

## Paso 2 — Analizar

Responsables:
- Codebase Mapper
- System Analyst

Acciones:
- Analizar la estructura.
- Identificar archivos afectados.
- Detectar dependencias.
- Evaluar impacto.

---

## Paso 3 — Revisar Arquitectura

Responsable:
- Architecture Reviewer

Acciones:
- Revisar arquitectura.
- Detectar deuda técnica.
- Identificar riesgos.
- Proponer mejoras.

---

## Paso 4 — Implementar

Responsable:
- Agente especialista correspondiente.

Ejemplos:
- Backend Engineer
- Frontend Engineer
- Python Django Engineer
- SQL Engineer
- AI Engineer

---

## Paso 5 — Seguridad

Responsable:
- Security Auditor

Acciones:
- Revisar vulnerabilidades.
- Revisar permisos.
- Revisar autenticación.

---

## Paso 6 — Calidad

Responsables:
- QA Engineer
- Testing Specialist

Acciones:
- Ejecutar pruebas.
- Validar cambios.
- Detectar regresiones.

---

## Paso 7 — Optimización

Responsables:
- Performance Optimizer
- Refactoring Engineer

Acciones:
- Optimizar rendimiento.
- Mejorar mantenibilidad.

---

## Paso 8 — Documentación

Responsable:
- Documentation Writer

Acciones:
- Actualizar documentación.
- Registrar cambios.

---

## Paso 9 — Liberación

Responsables:
- Git Manager
- Release Manager

Acciones:
- Revisar versión.
- Crear changelog.
- Preparar publicación.

---

## Regla General

Ningún agente debe saltarse pasos del workflow salvo autorización explícita.

Todas las respuestas y documentación deben estar en español.
