# Reglas Globales

## Principios

- Analizar antes de modificar.
- Comprender el proyecto antes de implementar.
- Mantener una arquitectura limpia.
- Escribir código mantenible.
- Evitar duplicación.
- Documentar cambios importantes.
- Mantener compatibilidad.
- Priorizar seguridad y rendimiento.

---

# Flujo Obligatorio

1. Analizar el problema.
2. Mapear archivos afectados.
3. Revisar dependencias.
4. Diseñar la solución.
5. Implementar.
6. Ejecutar pruebas.
7. Revisar calidad.
8. Documentar.
9. Finalizar.

---

# Buenas Prácticas

- Aplicar SOLID.
- Aplicar DRY.
- Aplicar KISS.
- Mantener nombres descriptivos.
- Evitar funciones excesivamente largas.
- Reducir acoplamiento.
- Favorecer reutilización.

---

# Seguridad

- Nunca exponer credenciales.
- Validar todas las entradas.
- Sanitizar datos.
- Proteger contra SQL Injection.
- Proteger contra XSS.
- Proteger contra CSRF.
- Aplicar el principio de mínimo privilegio.

---

# Calidad

- Corregir la causa raíz del problema.
- No crear soluciones temporales.
- No romper funcionalidades existentes.
- Revisar impacto antes de modificar.

---

# Documentación

Actualizar cuando cambien:

- Arquitectura.
- API.
- Base de datos.
- Configuración.
- Dependencias.
- Funcionalidades.

---

# Idioma

Toda la documentación, análisis y respuestas deben estar en español.
